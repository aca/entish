NAME

entish - scripting language and interactive shell for my next 10 years

MOTIVATION

For Unix users, every task begins at the shell. It is rarely taken seriously as a programming language, yet it is the glue of countless critical systems, and one of the few languages people still write by hand every day in AI era.

Most of that code targets bash and other POSIX shells, designed decades ago and full of gotchas and limitations.

fish, nushell, elvish, xonsh, rash and others have tried to do better. entish is one more attempt. It began as a personal project to rebuild elvish from scratch.

Source: github.com/aca/entish

KEY IDEAS

Types

POSIX shells cannot handle real data types, and that is the source of many gotchas. entish has types like a general-purpose programming language: str, num, bool, list, map, fn and nil. It never converts between them implicitly.

Two streams

The pipe | is not just connecting stdout to the next stdin. From a programming point of view, it is function composition: each command takes input and produces output, and | chains them into a larger function. But the UNIX pipe carries only bytes, so every stage has to print and parse text. entish keeps the UNIX pipe and extends it: every command has two output streams, a byte stream and a value stream. External commands write only to the byte stream; fns and builtins can also emit typed values to the value stream. | connects byte streams, |> connects value streams.

Both are real streams. All stages of a pipeline run concurrently, and values flow to the next stage one at a time as they are produced, just like lines through a Unix pipe.

Many modern shells have similar mechanisms. entish is more explicit: the two never mix, and nothing converts between them implicitly. Keeping them apart avoids a whole class of gotchas.

# nushell 0.112.2
$ echo 1 | od -c
0000000

# elvish 0.19.0
$ put 1 | od -c
0000000

# PowerShell 7.6.5
$ @{a=1} | od -c
0000000  \n   N   a   m   e  ...   V   a   ..

# entish
$ 1 | od -c
1:1: a value cannot be piped into
$ 1 |> print | od -c
0000000   1  \n
0000002

entish treats both pipes as function application. As in a Unix pipe, f's input is its stdin or value input, not its args:

a | f | g     ≡  g(f(a))
a |> f |> g   ≡  g(f(a))

To pass the value as an arg, use $_. The stage runs once per value with $_ bound to it:

a |> f $_ |> g $_   ≡  g (f a)

No loops, no word splitting, no quoting rules. Compare with bash:

# bash: $( ) output is split on spaces
$ for f in $(find . -name '*.log'); do echo "[$f]"; done
[./c.log]
[./my]
[logs/a]
[b.log]
# entish: a line is one value
$ find . -name '*.log' | lines |> echo "[$_]"
[./c.log]
[./my logs/a b.log]

# bash: a glob with no match is passed on as is
$ for f in *.mkv; do echo "got $f"; done
got *.mkv
# entish: it is an error
$ *.mkv |> echo $_
entish: no matches for *.mkv

# bash: the loop runs in a subshell, so n is lost
$ n=0; find . -name '*.log' | while read f; do n=$((n+1)); done; echo $n
0
# entish: values, not variables
$ find . -name '*.log' | lines |> count
▶ 2

LANGUAGE

A tour by example. Where an idea comes from another language, the heading says so.

Pipelines (from elvish)

# | carries bytes, |> carries values; lines turns bytes into values
$ ls | lines
▶ main.go
▶ go.mod
$ ls | lines |> count
▶ 2

# per-item work on values: extract the audio of each mp4
$ ls *.mp4 | lines |> each { |f| ffmpeg -i $f -vn -c:a copy $f.m4a }

# per-item logic: files over 1000 bytes
# (bash: while read f; do [ "$(stat -c %s "$f")" -gt 1000 ] && ...)
$ ls | lines |> each { |f| if (num $(stat -c %s $f)) > 1000 { $f } }
▶ big.bin

# a list stays a list: no word splitting, names with spaces are safe
# (bash: mapfile -t, or find -print0 | xargs -0)
$ let mp4 = ls *.mp4 | lines |> list
$ ls -1 ...$mp4
a b.mp4
c.mp4

# values stream through fns too: every statement of a fn emits
$ fn tag { each { "x$it" } }
$ tail -f log | lines |> tag |> print    # each line as it arrives

The item: $_ (from Hack and Perl)

# a stage after |> that uses $_ runs once per value; $_ goes where the item goes
$ ls | lines |> mv $_ $_.bak
$ ...[1 2 3] |> $_ * 2 |> list
▶ [2 4 6]

Functional, no loops

# each maps and filters; |> list collects, ...$xs spreads
$ ...[1 2 3 4 5] |> each { if $it % 2 == 1 { $it * $it } } |> list
▶ [1 9 25]

# recursion instead of loops; a generator is a fn that emits
$ fn fact n { if $n <= 1 { 1 } else { $n * (fact ($n - 1)) } }
$ fact 5
▶ 120
$ fn evens n { if $n > 0 { evens ($n - 2); $n } }
$ evens 6 |> list
▶ [2 4 6]

Conditions

# a command is tested by its exit status, ( ) by its value
$ if grep -q TODO main.go { print todo }
$ fn big n { $n > 9 }
$ if (big 10) { print big }
big
$ if big 10 { print big }       # compile error: big ends in a value, so as a
                                # command it always succeeds; to test it: (big ...)

Rational by default (from raku)

$ 0.1 + 0.2 == 0.3
▶ $true
$ round 4 (1 / 3)               # no silent rounding
▶ 0.3333

Multiline strings (from zig)

$ let name = "world"
$ let py =
    $\\name = "$name"
    \\print(f"hello {name}")
$ print $py | python3 -
hello world

EDITOR

Line editor

Written from scratch. Multi-line and vi-style; insert mode also accepts common emacs keys.

Terminal integration

Sets the window title (OSC 2), reports the working directory (OSC 7) and marks prompts and command output (OSC 133), so terminals can open new tabs in the same directory and jump between prompts.

History search

Ctrl-R searches command history with fzf-style queries. Enter puts the selection into your input, ready to edit or run.

Recent locations

Ctrl-D opens recent directories. Type to filter, then Enter to jump there.

Async completion

Tab gets command completions from Fish in the background, including options and their descriptions. Press it again to cycle through matches; Enter puts the selected one in without running.
